# Family OS — 詳細仕様

[← 玄関へ戻る](../README.ja.md) ｜ [← エンジニア向けドキュメント](engineering.ja.md)

地図の背後にある正確な契約です。どの事実を誰が所有するのか、どのエッジが存在するのか、証拠が来なかったときに何が起きるのか。[エンジニア向けドキュメント](engineering.ja.md)が形を散文で説明し、このページがそれを固定します。

<a id="scope"></a>

## 適用範囲と読み方

この文書は決定の記録ではなく、**いまの契約**です。今日成立していることを述べます。

読み方は4つのルールに従います。

- **1つの問いに、1つの権限。** 下の各問いには、答えてよいモジュールがちょうど1つあります。それ以外は全員が観測者です。
- **ポインタは複製ではありません。** ここで他モジュールの契約に触れていても、正本はそのリポジトリです。食い違ったらモジュール側が正で、このページは誤りです。
- **形は許可ではありません。** `提案` の行は、検討された形を示すだけです。実装・認証情報・新しい消費者を承認しません。
- **不在は `unknown` です。** 証拠が届かないときの正しい結果は `unknown` かローカルの進捗の保持であって、合成された成功ではありません。

<a id="claim-states"></a>

## 主張の状態

| 状態 | 意味 | この上に作ってよいか |
| --- | --- | --- |
| `実装済み` | 今日存在し、証拠に裏付けられている | よい |
| `決定済み` | 受け入れられた境界または慣行 | 境界としてよい |
| `提案` | 形のみ・承認された消費者はいない | いけない |
| `不明` | 唯一の権限者が答えるまで、いかなる事実も推論してはならない | いけない |

`提案` のエッジは、その契約所有者がバージョン交渉・移行・ロールバックまたはダウングレードの挙動を記録するまで、消費者を持てません。

## ノード

| ノード | 種別 | 所有するもの | 依存してよいもの | 依存しても・なってもいけないもの |
| --- | --- | --- | --- | --- |
| Family OS | non-runtime・連携 | 家族の方針・論理地図・ポインタ・観測の描画 | 読み取り専用のモジュール／記憶バス出力（帯域外） | runtime コールバック・レジストリ・制御装置・秘密の保管庫・死活の権限 |

| Persona Growth Loop | 計画中のフロントエンド | 最小化された冪等な提案の生成 | 将来の成長 intake のみ | 基盤・台帳・採用・スケジューラへの直接権限 |
| オーナー | 外部権限 | identity に関わる承認 | 帰属可能な意思決定の面 | runtime モジュールによる代替 |

| プロバイダアダプタの所有者 | 外部権限 | 相関づけられたリモートの状態・キャンセル事実 | プロバイダ API | 基盤や Sitter による捏造 |
| 消費者・転送の所有者 | 外部権限 | 実際の受領事実 | 転送の契約 | プロセス終了を配送と解釈すること |
| メトリクス源 | 外部権限 | メトリクスの観測値 | 計測の情報源 | 成長ループによる捏造 |
| デプロイ運用者 | 外部権限 | 認証情報・スケジューラ・break-glass・機構所有者の宣言 | 具体的なデプロイ | Family OS の秘密・制御経路 |

依存の向きとして許されるもの:

1. non-runtime の文書は、帯域外でポインタと事実を読む。
2. runtime モジュールは、前に進むために Family OS や掟を必要としない。
3. 要求は次の判断を所有するモジュールへ流れ、証拠は権限を移さずに戻る。
4. 記憶バスが受け取るのは境界づけられた基盤エンベロープであって、モジュールの可変状態ではない。
5. 任意・提案のエッジは、ローカルの進捗の保持か `unknown` として失敗する。

<a id="authority"></a>

## 権限

各問いには、権限を持って答える者がちょうど1人います。最後の列は、証拠が届かなかったときに記録しなければならないものです。

| 問い | 唯一の権限 | 観測してよい者 | 明示的に権限を持たない者 | 証拠が無いときの姿勢 |
| --- | --- | --- | --- | --- |
| このタスクは何を意味するか | 基盤 | 成長ループ（宣言された基準を通じて） | Sitter・記憶バス・Family OS | タスクは基盤の中で未解決のまま |
| 現在の試行はどれか | 基盤 | Sitter（明示的に委譲された試行 id について） | Sitter の再起動カウンタ・記憶バス | 試行を進めない |
| リトライか、完了か、DLQ か | 基盤 | 成長ループは終端結果を解釈してよい | Sitter・プロバイダ・受領証・記憶バス | 基盤が所有する pending か `unknown` |
| 監督されたローカルのプロセスは終了・停滞したか、期待した返信を出したか | Sitter | 呼び出し元の基盤 | 基盤のタスク終端状態・プロバイダアダプタ | Sitter のローカル事実は `unknown` |
| Sitter は明示的な同一試行の再起動を行ったか | Sitter | 基盤 | Sitter が新しい試行を決めること | 再起動も結果も推論しない |
| 相関づけられたリモートの状態・キャンセル結果は何か | プロバイダアダプタの所有者 | 呼び出し元の基盤 | プロセス終了・Family OS | 呼び出し元はリモート状態を `unknown` のまま保つ |
| 消費者は実際に受け取ったか | 受領証・転送契約の所有者 | 呼び出し元の基盤 | プロセス終了・プロバイダの完了・Sitter の返信観測 | 配送は `unknown` のまま |
| 登録されたジョブは期待されていたか、その check-in は届いたか | 記憶バス | Family OS の描画された観測 | モジュールのタスク状態・機構の健全性 | 記憶バスの契約に従い stale または欠落 |
| その check-in を生成した producer・ホスト・source・転送・宛先はどれか | 記憶バスの来歴プレーン（宣言された identity から） | Family OS | 全モジュール共通の writer レジストリ | 旧来の identity は来歴 `unknown`・基本の死活は継続 |
| 具体的なヘルパー機構はインストール済み・実行可能・ロールバック済みか | その機構の所有者 | 運用者・記憶バスは宣言された check-in を観測してよい | Family OS・タスクのドメイン・記憶バスの汎用プレーン | 機構の健全性は `unknown` または degraded |
| 登録されたスケジュールは生きているか | 記憶バス | 運用者・Family OS のビュー | ヘルパーの健全性だけで判断すること | スケジュールの死活は `unknown` または stale |
| この文書は鮮度メタデータに照らして最新か | Family OS の文書プレーン | 人とエージェント | runtime の健全性・死活 | 観測を stale または `unknown` と記す |
| 開発ワークフローの契約は何か | Family Dev Handbook | 開発者とエージェント | runtime モジュール | ガバナンスの指針が利用不能 |
| どの提案・定足数・採用の記録が存在するか | 成長ループ | 人とエージェント | 人格モジュール・基盤・Family OS | 直前の有効な状態か `unknown` のまま |
| オーナーはこの identity に関わる遷移を承認したか | オーナー（永続的で帰属可能な参照によって証拠づけられる） | 成長ループがその参照を記録する | フラグや actor 文字列・参照のないエージェントの中継 | fail closed・承認は `unknown` |
| 変更は採用されたか | 成長ループ | 突き合わせたビュー | オーナーの承認だけ・対象の所有者 | 採用記録は `unknown` または pending |
| 対象は変更を適用または取り消したか | 対象の所有者 | 成長ループ（相関づけられた受領証を通じて） | 採用記録・基盤のタスク完了 | 適用・取り消しは `unknown` のまま |
| 観測されたメトリクスの値は何か | メトリクス源 | 成長ループの評価プロトコル | 成長ループによる捏造 | メトリクスは `unknown` |
| 採用された変更は有効だったか | 成長ループの評価プロトコル（メトリクス源の事実を用いる） | 人とエージェント | 採用や適用だけで判断すること | 有効性は `unknown` または pending |
| ここでの認証情報・スケジューラ・break-glass は誰のものか | 宣言されたデプロイ運用者 | 具体的なモジュールまたは機構 | Family OS・掟・記憶バスの汎用プレーン | 操作は fail closed |

<a id="vocabulary"></a>

## 曖昧な語の分割

モジュール間の混乱の大半は7つの語から生まれます。1つの事実に聞こえて、実は複数だからです。それぞれ所有者はちょうど1人です。

| 語 | 所有者 | よくある誤解 |
| --- | --- | --- |
| `returned` | リモートの結果はプロバイダアダプタ・Sitter が言えるのはローカルの返信観測だけ・タスクの解釈は基盤 | 3つのうち1つが他の2つを兼ねること |
| `ack` | 消費者の受領確認は転送の受領証所有者・記憶バスが持つのは自身の check-in 受領のみ | 1つの受領確認が両方をカバーすること |
| `delivered` | 消費者・転送の所有者 | プロセス終了・プロバイダの終端状態 |
| `healthy` | 機構の健全性は機構の所有者・登録スケジュールの死活は記憶バス・文書の鮮度だけが Family OS | 1つの健全性がシステム全体を表すこと |
| `adopted` | 成長ループのガバナンス記録 | 対象が実際に変わったこと |
| `applied` | 対象の所有者 | 採用の記録 |
| `effective` | 成長ループの評価プロトコル（メトリクス源の事実を用いる） | 採用・適用 |

<a id="forbidden"></a>

## 存在しないエッジ

以下のエッジは存在せず、追加してはいけません。どれも引いた瞬間に、観測が制御に変わります。

- Family OS → いずれかの runtime モジュール
- Family Dev Handbook → いずれかの runtime モジュール
- 人格モジュール → 基盤またはいずれかの台帳
- Sitter → 記憶バスのタスク状態、または基盤のタスク判定
- 記憶バス → モジュールの可変状態
- 成長ループ → 対象の内部状態（許されるのは将来の公開要求のみ）
- リポジトリの分割 → 権限（分けても何も得られない）

<a id="removal"></a>

## 取り外しの不変条件

- Family OS を外すと、連携の見通しが失われます。runtime の状態は失われません。
- 掟を外すと、ガバナンスの指針が失われます。runtime の稼働は失われません。
- 記憶バスを外すと、記憶と check-in の観測が失われます。各モジュールのドメイン状態は残ります。
- Sitter を外すと、任意の外部監督が無効になります。基盤はタスクの意味論を保持し、ローカルの失敗時の姿勢を使います。
- 成長ループを外しても、基盤のタスクと証拠はそのまま残ります。失われるのは成長のガバナンスだけです。
- ヘルパー機構を外しても、対象やドメインの事実を書き換えてはいけません。

<a id="unknown"></a>

## unknown の姿勢

未割当の所有者・消費者・スキーマ・移行・ロールバック・ダウングレードの挙動は、名指しされた権限者が公開契約を記録するまで未割当のままです。このページはそれらを解決できません。地図にもできません。

これは意図的です。モジュールに代わって unknown を解決する地図は、連携の層が静かに制御装置へ変わっていく道であり、観測していない成功をシステムが報告しはじめる道です。
